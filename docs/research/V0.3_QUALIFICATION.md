# V0.3 Natural Repository and Defensive Evidence Qualification

## Outcome

V0.3 records two independent states:

- Trace Code programme: `DATA_GATES_PENDING`
- Trace IR feasibility lane: `IR_FEASIBILITY_SUPPORTED`

The Trace Code decision is a valid stop state, not a performance result. The
governed store contained no admitted natural repositories or candidate-ranking
groups, so the unchanged V0.1 runtime was not run against a natural development
or qualification partition. No threshold was set and the frozen holdback
remained unopened.

The Trace IR decision applies only to four Skylark-authored, inert lab episodes
with matched benign controls. It is an architecture-feasibility result, not a
claim of live attack detection, actor attribution, containment capability, or
natural telemetry performance.

## Trace Code Contracts

Every controlled-reviewed location declares one of:

- `OBSERVATION`
- `HARNESS`
- `WITNESS`
- `VULNERABLE_IMPLEMENTATION`
- `CONTRIBUTING_IMPLEMENTATION`
- `FIX_SITE_ONLY`

File, symbol, region, and role-correct matches are scored separately. A harness
or observation path does not become a vulnerable implementation label merely
because a report or fixing revision mentions it. Multiple accepted targets
must be explicit, and ambiguous labels are excluded from primary denominators.

Primary safety views include false vulnerability on safe controls, false
`SUPPORTED` dispositions, wrong-role top-one results, hard-negative outrank,
unsafe non-abstention, and unsupported-input acceptance. Counts and rates are
both retained. Retrieval uses Recall@1, @5, @10, and @20, MRR, indexability,
no-candidate rate, and separate repository and repository-family macro views.

## Natural Corpus Decision

V0.3 looked only for records already admitted to the governed G: store. It did
not download repositories, infer rights, consume benchmarks, or repurpose
historical evidence. The admitted counts were:

| Measure | Observed | Pilot target |
| --- | ---: | ---: |
| Accepted groups | 0 | 50-100 |
| Unrelated repositories | 0 | 8-12 |

Consequently, construction, development, qualification, and holdback runs did
not occur. The empty split is still hash-bound, the qualification budget is
zero, and `FROZEN_UNOPENED` is preserved.

## Trace IR Boundary

Trace IR operates only on copied JSON packages. Normalisation:

- bounds event count, nesting, item count, and string length;
- accepts only exact inert fields;
- rejects remote references, template syntax, executable fields, secret-like
  strings, forged custody, unredacted input, and protected partitions;
- derives canonical event and episode identities;
- keeps controlled-review labels in a separate sealed package; and
- exposes no action or integration endpoint.

Deterministic ranking uses a small declared action vocabulary, event outcome,
stable order, and matched approved-maintenance context. Source text is never
evaluated. Raw results are sealed before labels are scored, and replay compares
result identities.

## Commands

```text
trace-eval code metric-specification --output metric.json
trace-eval ir normalise episode.json --output normalised-package
trace-eval ir rank normalised-package --output result-package
```

There is no CLI command for live collection, response action, training, model
download, or frozen-holdback execution.

## Private and Public Evidence

Full rights records, private manifests, event packages, labels, controlled
review, raw results, scored results, and resource observations remain under
the governed F:/G: topology. The repository seal contains only disclosure-safe
contracts, counts, hashes, decisions, and summaries. It contains no natural
repository source or event substance.

The controlled review is a controlled internal release review. It is not
described as a third-party audit.
