# Lumi Trace V0.7.1 assurance summary

V0.7.1 adds bounded multi-result SARIF triage without changing the V0.6.1
ranker. A batch command snapshots and indexes one local Python repository once,
then produces per-finding unique-path shortlists and one deterministic reviewer
queue.

## Confirmation

The release-candidate workflow was checked against 30 findings across pinned
public Flask, Requests, and HTTPX revisions. SARIF was produced with pinned
Bandit 1.9.4 in a separate confirmation environment. Repository code was not
installed, imported, built, tested, or executed.

- 30 of 30 normalized findings matched standalone trace exactly.
- 30 of 30 candidate sets, rankings, and identities matched exactly.
- All three batch packages and all 30 standalone packages verified.
- No admitted result was lost, rejected, or silently truncated.
- The confirmation covered nine scanner rule IDs and two supplied SARIF levels.

These results demonstrate batch/standalone workflow parity and evidence-package
integrity on the reviewed set. They do not measure vulnerability-discovery
accuracy, establish population performance, or show that any repository is
safe or vulnerable.

## Product boundary

- deterministic Python-focused localisation for supplied findings;
- zero runtime dependencies and zero packaged model weights;
- no product network request, hosted inference, telemetry, or API key;
- repository code treated as untrusted data and not executed during triage;
- queue order is review priority, not probability or exploitability; and
- malformed individual results are explicit verified errors, not silent loss.
