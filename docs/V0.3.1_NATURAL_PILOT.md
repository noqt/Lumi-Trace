# Lumi Trace V0.3.1 Governed Natural Pilot

Lumi Trace V0.3.1 adds the governed intake and evaluation controls needed to
measure the unchanged V0.1 deterministic baseline on public, permissively
licensed natural repositories. It does not change the V0.1 runtime, open the
protected holdback, train a model, acquire weights, or publish third-party
source.

## Authority and scope

The user-approved V0.3.1 build brief authorises:

- proposal and rights precheck before repository transport;
- explicit acquisition approval;
- inert acquisition of exact public revisions;
- private evaluation and controlled label construction;
- repository-family-disjoint development and qualification partitions;
- one qualification run only if the predeclared development gates pass; and
- disclosure-safe aggregate evidence.

The authority excludes customer and private repositories, CyberGym,
historical Lumi or Lumi Scout evidence, protected holdbacks, repository build
or setup execution during intake, model training, weight acquisition, and
public release without a further user decision.

## Intake state machine

```text
PROPOSED
  -> RIGHTS_PRECHECK_PASSED
  -> ACQUISITION_APPROVED
  -> ACQUIRED_UNADMITTED
  -> ADMITTED_FOR_EVALUATION
```

Any pre-admission state may fail closed to `REJECTED`; an admitted or rejected
record may later become `RETIRED`. Only an approval record whose decision was
sealed before fetch authorises transport.

Rights are recorded independently for source access, private evaluation,
source redistribution, finding use, label use, future training use, and future
weight licensing. Future training and weight rights default to false and
`NONE`, respectively.

## Inert Git boundary

The generic intake builder:

- accepts only canonical public HTTPS GitHub repository URLs;
- pins full immutable commit identifiers;
- isolates system and global Git configuration;
- disables hooks, submodule recursion, LFS smudge, checkout filters, prompts,
  external protocols, and remote configuration includes;
- performs a bare object fetch without checkout;
- rejects unsafe or non-portable paths, special files, and configured size
  limits before materialisation;
- retains symlink and submodule objects as hash-bound inert references without
  resolving or materialising them;
- writes only regular blobs into a clean snapshot;
- recomputes the V0.1 `lumi-tree-sha256-v1` identity; and
- binds transport, commit, tree, licence, scan, and snapshot identities in an
  acquisition receipt.

No repository package install, build, test, setup, generator, hook, filter, or
other repository-controlled command is part of intake.

## Labels and runner separation

Labels are constructed from public security evidence and the old-line side of
an authoritative fixing diff. Python syntax trees are parsed as data; source
is never imported or executed. The construction pass records vulnerable
implementation locations, test or reproduction harness hard negatives, safe
fixed controls, ambiguity, evidence strength, and correction history.

A separate controlled-review pass occurs before any runtime output exists. It
checks exact-revision licence evidence, pair identity, role semantics,
ambiguity, and the intentionally absent reproduction plan. The runtime view
contains opaque snapshot and group identifiers, the natural finding, and the
repository snapshot. It does not contain:

- accepted locations;
- fixing diffs;
- safe or vulnerable state;
- revision roles;
- hard-negative labels;
- reviewer notes; or
- qualification labels.

Cue ablations are diagnostic only and never increase natural group counts or
enter qualification.

## Split and execution policy

The split unit is the upstream repository family and all shared history,
forks, mirrors, transformed variants, vulnerable/fixed pairs, and duplicate
vulnerability lineages. No family may cross development and qualification.

The pre-run seal binds:

- the exact V0.1 wheel;
- the V0.3.1 evaluator wheel;
- corpus and split identities;
- evaluator configurations;
- metric specifications;
- predeclared performance thresholds;
- fixed integrity floors; and
- a qualification budget with a maximum of one run.

Development output is sealed before evaluator-only labels are applied.
Deterministic replay is required. Qualification is allowed only after the
development threshold decision and is not used for threshold selection or
remediation.

## Evidence boundary

Private governed storage retains proposals, approvals, advisory records,
source snapshots, exact licence evidence, revision mappings, fixing diffs,
labels, review receipts, registries, raw output, scored output, replay, and
decision records.

The repository may retain only code, schemas, tests, documentation, aggregate
counts and metrics, non-sensitive identities, decisions, hashes, and
verification instructions. It must not contain repository names, source,
source excerpts, case-level findings, locations, revisions, fixing diffs, raw
outputs, reviewer notes, credentials, or private paths.

## Current result

The final corpus counts, unchanged-baseline metrics, threshold decision,
qualification-budget use, closure state, evaluator identity, and public
evidence seal are recorded in [V0.3.1 Evidence](V0.3.1_EVIDENCE.md).

Regardless of pilot outcome, V0.3.1 cannot authorise `TRACE-001`. Training
still requires at least 500 useful labelled groups, 25 unrelated repositories,
repository-disjoint development and holdback sets, audited labels, adequate
deterministic recall, explicit training-data and weight licensing, a model
card, training code, evaluation manifests, foundation-model licence
verification, and reproducible local inference.
